# 独立实时监测

底部「练习」模块提供实时基频与实时频谱两个独立页面，各自拥有本次监测的音频、图表和播放状态。

- **实时频谱**：显示 40–8000 Hz 对数频率坐标、dBFS 幅度和当前频谱峰值。
- **实时基频**：沿用 Core 的 SwiftF0 检测，显示当前 Hz 和随时间变化的基频曲线；无声或不可信检测保留为断点。

## 操作约定

1. 点击 Tab Bar 上方配件右侧的红色圆形主按钮申请麦克风权限并开始采集。
2. 采集或回放时再次点击主按钮会暂停并保留当前缓存；暂停后点击主按钮会从已有录音的末尾继续采集，暂停期间不增加音频时间。
3. 点击顶部导航栏的时长菜单选择 5、10 或 30 秒窗口。窗口结束于当前定位点，长度不足时使用实际保留的音频。
4. 底部配件中的「回退 5 秒」会从当前定位点前 5 秒开始，连续播放到本次回放的实时尾部；页面时间轴拖动则暂停播放并移动定位点，最早只能回到仍保留的位置。
5. 点击底部配件中的「回放」会从当前定位点播放到实时尾部；定位点在实时边缘时重放最后一个窗口。图表使用所选 5/10/30 秒固定时间窗口，播放到达窗口末端时翻到下一页，最后一页对齐回放尾部；频谱、基频读数和游标跟随播放器时钟。若回放从实时采集中发起，播放结束后自动恢复采集；从暂停状态发起的回放结束后保持暂停。
6. 缓存只保留最近 60 秒；离开监测页面或切出练习 Tab 时清空，不生成录音文件，也不写入练习/评估历史。

系统进入后台、失去焦点、音频中断或输入设备改变时停止音频活动。系统权限弹窗导致的暂时失焦会等待页面重新激活后才启动；后台和离开仍会取消准备操作。使用现有音频会话租约，其他录音进行中时明确报错，不接管其麦克风。

## 界面

详情页采用全屏仪表布局：原生大标题下显示紧凑的当前频率读数，实时基频页补充当前窗口内的实际基频范围，实时频谱页补充当前峰值的 dBFS 幅度。图表使用透明、无边框画布并占满剩余高度，有音频后浏览时间轴显示在图表下方。

页面保留 Tab Bar，并与录制页共用 Tab Bar 上方的系统底部配件容器。配件从左到右依次为对应页面图标、静态页面标题、回退 5 秒按钮、回放按钮、红色录制/暂停主按钮。主按钮采用与录制页一致的圆形外观：未采集时为 `record.circle`，采集或回放时为 `stop.circle`，继续承担开始、暂停和继续采集的语义。

三个操作按钮均提供 44 点触控区域，并共用录制按钮的按下缩放与透明度反馈；禁用时变淡且不触发按下反馈。轻触觉只在有效用户操作确实改变监测状态或定位时间时触发。

页面时间轴用于拖动定位，窗口时长从顶部导航栏菜单调整。频率读数与图表保留在页面内容中；读数说明位于图表下方，完整监测规则可从导航栏的说明按钮查看。

## 实现

- `MonitorAudioCapture` 将硬件 PCM 转为连续 16 kHz 单声道样本。输入队列最多容纳 2 秒或 128 个缓冲区，串行处理器等待主线程接收后才释放容量；处理不及时会明确停止，不能默默丢样本或无限排队。
- `MonitorSpectrumAnalyzer` 使用 2048 点 Hann FFT，1600 样本步进；每秒约 10 帧，频点间距 7.8125 Hz，幅度按 dBFS 校准。
- `MonitorTimeline` 用固定 960,000 个 Float 的环形缓冲保存 PCM，分析帧按相同时间范围淘汰。播放截取采用 `[start, end)`，相邻窗口不重复边界样本。
- `MonitorViewModel` 以每次操作的 generation 和会话 owner 隔离取消/旧回调，恢复时重置检测上下文并加上累计采集时间。
- `MonitorWaveEncoder` 生成内存 PCM16 WAV，`AVAudioPlayer.currentTime` 驱动实际回放位置。回放时将「定位点到实时尾部」一次编码，`playbackPage` 只控制固定时间窗口的翻页；音频连续播放，不按窗口重新切分 PCM。回放时暂停麦克风，避免扬声器音频再次进入监测。

## 验证

- `Scripts/test-monitor-timeline.sh`：环形覆盖、短片段、逐样本截取、连续回退、时间边界、静音、分析帧淘汰、恢复时间戳，以及用 AVAudioFile/AVAudioPlayer 验证实际 WAV 解码与 5/10/30 秒播放时长。
- `Scripts/test-monitor-spectrum.sh`：频率峰值、幅度校准、DC/Nyquist、双音、静音、分块不变性和重启。
- `Scripts/test-live-f0.sh`：现有实时基频管线，并验证已取消的重置不会修改仍在使用的检测时间线。
- Xcode 的 Pitchee Debug 模拟器目标完整构建。

已在 iPhone Duo（iOS 27.1）模拟器完成布局与回放截图验证。

Debug 构建支持以下可组合的启动参数，用于独立检查监测界面。入口仍经过应用主界面；首次引导尚未完成时，需要先完成引导：

- `-monitor-review-pitch` / `-monitor-review-spectrum`：直接进入实时基频或实时频谱页面，两者选一。
- `-monitor-preview-data`：注入内存中的合成音频、基频与频谱数据，初始状态为暂停；生成这组 fixture 不连接麦克风、不申请音频会话，也不读写用户记录。省略该参数可查看未开始状态。
- `-monitor-review-dark`：将上述预览入口设为深色外观。
- `-monitor-review-large-text`：将上述预览入口设为辅助功能字号 `accessibility2`。

这些参数与 fixture 仅存在于 Debug 构建。fixture 用于视觉检查；主动点击「开始」或「继续」仍会进入正常采集流程，真实麦克风、权限及回放行为需要另行验证。

新增的 51 个本地化键覆盖现有 29 种语言。非中英文翻译沿用仓库的 `needs_review` 标记。全仓本地化脚本的既有 35 个问题与 HEAD 基线相同，新增监测键未增加错误。

真机还应检查麦克风权限、扬声器/蓝牙路由、来电中断及长时间采集的设备表现；自动化音频测试使用合成信号，不替代真机声学验证。
